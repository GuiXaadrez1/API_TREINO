# Introdução

Esse arquivo visa explicar os comandos que utilizamos para manipularmos nosso prisma da forma mais suncinta e eficiente possível.

## prisma generate: 

Comando: npx prisma generate --schema=prisma/schema.prisma

Objetivo: Esse comando gera o Prisma Client, ou seja, os arquivos TypeScript/JavaScript que representam os modelos definidos no seu schema.prisma.

Como funciona:

- Lê seu arquivo schema.prisma para identificar os modelos, relacionamentos, configurações do banco e do generator.

- Com base nessas definições, o Prisma gera uma biblioteca interna contendo funções já prontas para manipular o banco via código (ex: prisma.user.findMany()).

- Essa biblioteca é tipada, ou seja, o TypeScript sabe exatamente os campos que existem, os tipos, as relações, etc.

Onde ele gera o client?

- Por padrão: node_modules/@prisma/client

- Se usar output no generator, será no caminho customizado (ex: output = "./generated/client")

Quando usar?

- Após qualquer alteração no schema.prisma

- Após rodar npx prisma db pull (quando você puxa estrutura de um banco existente)

- Sempre que clonar um projeto que já usa Prisma

## prisma migrate:  

Comando: npx prisma migrate dev --schema=prisma/schema.prisma

Objetivo: Cria uma nova migração e aplica automaticamente as alterações no banco de dados em ambiente de desenvolvimento.

Como funciona:

- Compara o schema atual com o histórico de migrações já aplicadas.

- Gera uma nova pasta dentro de prisma/migrations/ com SQL que descreve as alterações.

- Executa o SQL no banco automaticamente.

- Também executa o prisma generate ao final (por isso não precisa chamar depois).

Exemplo: Se você adicionar um novo campo idade Int no model User, esse comando criará um script SQL para adicionar a nova coluna idade na tabela User.

Requer nome da migração: 

- Ao rodar manualmente no terminal, você precisa informar um nome, exemplo:

npx prisma migrate dev --name add-idade

Quando usar?

Toda vez que você modificar o schema (adicionar/remover campos, modelos, relações)

Em fase de desenvolvimento (não recomendado para produção)

## prisma studio

Comando: npx prisma studio --schema=prisma/schema.prisma

Objetivo: Abre o Prisma Studio, uma interface gráfica de administração de dados no seu banco.

O que ele oferece:

- Visualização em tempo real das tabelas (models)

- Inserção manual de registros

- Edição e exclusão de dados

- Visualização de relações (ex: ver os posts de um usuário)

Interface:

Ele roda localmente em http://localhost:5555 por padrão.

Quando usar?

- Quando você quer testar dados diretamente

- Quando quiser preencher manualmente tabelas durante o desenvolvimento

- Para validar se os dados estão salvos corretamente

## prisma migrate reset

Comando: npx prisma migrate reset --schema=prisma/schema.prisma

Objetivo: Reseta completamente o banco de dados - apaga tudo, reaplica todas as migrações e (se configurado) executa um script de seed.

Como funciona? 

- Remove todas as tabelas do banco (⚠️ isso apaga tudo).

- Aplica todas as migrações novamente na ordem.

- Executa o arquivo prisma/seed.ts (se definido em package.json).

- Gera novamente o Prisma Client ao final.

Quando usar?

- Ao fazer muitos testes e precisar "voltar ao início"

- Para simular uma criação de banco limpa

- Em ambiente de desenvolvimento

Cuidado! Nunca usar em produção: Destrói os dados existentes.

## prisma db pull 

Comando: npx prisma db pull --schema=prisma/schema.prisma

Objetivo: Importa a estrutura atual de um banco de dados existente (tabelas, colunas, tipos, etc.) e atualiza o schema.prisma automaticamente.

Como funciona:

- Conecta ao banco de dados via DATABASE_URL

- Lê todas as tabelas, campos e chaves estrangeiras

- Atualiza o schema.prisma para refletir o banco real

Quando usar? 

- Quando você já tem um banco existente e quer usar Prisma nele

- Quando alguém altera o banco diretamente (sem usar migrations)

- Quando deseja sincronizar seu schema local com o banco real

Dica: Após rodar, use prisma generate para gerar o client com base no novo schema.

## Conclusão e ordem típica de uso:

1. Você cria ou altera models no schema.prisma

2. Roda prisma:migrate para aplicar as mudanças

3. Usa prisma:generate para atualizar o Prisma Client

4. Usa prisma:studio para inspecionar/editar dados

5. Em testes: usa prisma:migrate-reset para recriar o banco do zero

6. Se está importando um banco existente: usa prisma:pull
